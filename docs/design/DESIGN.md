# 掃地工作小幫手：設計規範

> 狀態：定案（v2.13「點名表」，取代 v2.12 的設計）。最後更新：2026-10-25。改任何頁面、版面、元件、樣式前先讀這份。要偏離，先更新本文件並取得使用者確認。

- 定案的模擬頁：[docs/design/mockups/抽籤工作台.html](mockups/抽籤工作台.html)（手機、iPad、桌機；開啟後可切換深淺色）
- 規範的實際樣式在 `index.html` 最上方 `<style>`：`:root` 是 tokens，其後是元件。本文件是它的說明，兩者不一致時以使用者確認過的本文件為準，並修正程式。
- 範圍：只改視覺與版面，功能與資料流程不動。
- 這份規範只管這個程式，不做跨程式共用的元件庫。

## 1. 設計原則

1. **看得清楚比好看重要。** 白紙黑字，字夠大、對比夠高。使用者曾因為花俏、看不清楚而退回兩版設計。
2. **全站只有一個強調色（藍）。** 它只表示三件事：可以按（主要按鈕）、目前所在（目前頁、選到的項目）、焦點。其他一律灰階。
3. **不靠顏色分類。** 工作類別、辛苦、指定都用文字與反白標記（黑底白字的「🔨 辛苦」「指定」），不要再為它們加顏色。
4. **抽籤是主角。** 「抽全部」是畫面上唯一的實心藍色大按鈕；其他動作都是白底外框按鈕。
5. **手機與 iPad 先考慮拇指。** 點擊區 ≥ 48px；最常按的抽籤按鈕固定在底部頁籤列上方。
6. **emoji 只用在有意義的地方**：導覽、工作項目圖示（使用者資料）、🔨 辛苦標記、按鈕上的功能圖示。標題、統計、區塊標題不放裝飾 emoji。

## 2. Tokens

全部用 `#RRGGBB`。不要用 `oklch()`、`color-mix()`：html2canvas 無法解析，匯出圖片會失敗。

|---|---|---|---|
| `--bg` | `#F2F3F5` | `#0B0C0E` | 頁面底 |

| `--surface-2` | `#ECEEF1` | `#1F2226` | 凹陷底、辛苦的列、次要面 |
| `--surface-3` | `#DDE0E5` | `#2B2F35` | 座號底、開關軌道、懸停加深 |
| `--line` | `#D3D7DD` | `#2F343A` | 分隔線 |
| `--line-strong` | `#78818D` | `#7D8693` | 按鈕、輸入框、名牌外框（對底色 ≥ 3:1） |
| `--text` | `#0F1318` | `#F5F6F8` | 主要文字 |
| `--text-2` | `#333A43` | `#CDD2D9` | 次要文字 |

### 字型

| 用途 | 字型 | 字級／行高 | 字重 |
|---|---|---|---|
| 全站 | Noto Sans TC（Google Fonts），備用 system-ui、PingFang TC、Microsoft JhengHei | | 400、500、700 |
| 頁面標題 | | 28（iPad 30、桌機 32）／1.25 | 700 |
| 區塊標題 | | 20–22／1.3 | 700 |
| 工作名稱、姓名 | | 17–19 | 700 |
| 內文、清單、按鈕、輸入框 | | 16（輸入框 ≥ 16，避免 iOS 放大） | 400、500、700 |
| 輔助說明、標籤 | | 14（最小 14，頁尾也一樣） | 500、700 |

數字對齊的地方（人數、座號、時間）加 `font-variant-numeric: tabular-nums`。

### 間距、圓角、陰影、動態

- 圓角：`--r-sm` 8、`--r-md` 10、`--r-lg` 14、`--r-xl` 20。
- 邊框：控制項用 1.5px `--line-strong`；卡片用 1px。卡片不用淡色底，也幾乎不用陰影。
- 間距：4 的倍數；區塊間距 20（桌機 24），卡片內距 16。
- 動態：只用在狀態變化（懸停、按下、彈窗滑入、提示訊息淡入）。抽籤動畫是功能，保留原本六種。

## 3. 版面與斷點

斷點用 `min-width`，由手機往上加。

| 寬度 | 導覽 | 抽籤按鈕 | 備註 |
|---|---|---|---|
| < 768（手機） | 頂部窄欄（品牌、深淺色、備份）＋底部頁籤列（5 個，emoji＋短名） | 固定在底部頁籤列上方 | 單欄；分配表每個工作一列，姓名排在下方；工作清單變卡片；彈窗是底部滑出的面板 |
| 768–1023（iPad 直向） | 左側窄軌（96px） | 在頁面內 | 分配表三欄：工作、姓名、清空 |
| ≥ 1024（桌機、iPad 橫向） | 左側欄（256px，完整名稱、深淺色切換、備份） | 在頁面內 | 內容最寬 1160px；點擊區縮到 44 / 38 |

頁籤名稱：完整名稱用在側欄與頁面標題（抽籤工作台、名單管理、掃地工作項目、歷史記錄、系統設定），短名用在底部頁籤與窄軌（抽籤、名單、工作、紀錄、設定）。

## 4. 元件規則

- **按鈕** `.btn`：預設是白底外框；`btn-primary` 是唯一的實心藍；`btn-soft` 藍色淡底；`btn-danger` 白底紅字紅框；`btn-ghost` 無框。尺寸：`btn-lg` 56、預設 48（桌機 44）、`btn-sm` 48（桌機 38）、`btn-icon` 正方形。停用透明度 .45。
- **重設規則的優先序要是 0**：全域重設只能寫 `:where(.app) button { font: inherit; color: inherit }`。直接寫 `.app button` 會蓋掉 `.btn-primary` 的文字色（v2.12 曾因此造成主要按鈕文字看不清楚）。
- **匯出按鈕** `.xbtn`：一般白底外框按鈕，emoji＋名稱，不加品牌色。手機上五顆排成一列，emoji 在上。
- **座號名牌** `.tag`：左側座號（灰底、粗體），右側姓名（17px 粗體），1.5px 外框。「指定」是名牌內的黑底白字小標；空缺 `.tag-empty` 是虛線框；抽籤中 `.tag-draw` 是藍色虛線框。
- **分配表** `.roster` ＋ `.rrow`：一列一個工作。左側是圖示、名稱（辛苦的後面加黑底「🔨 辛苦」標記）、說明、類別標籤與人數；右側是姓名名牌；最右是 🗑️ 清空。辛苦的列用 `--surface-2` 底並排在最上面；抽籤中的列用藍色內框。
- **標籤**：`.badge` 是灰字外框（類別）；`.chip` 是白底外框，`chip-primary` 藍色淡底（完成、剛好符合），`chip-danger` 紅色淡底（缺人手），`chip-heavy` 反白（辛苦）。
- **表單**：`.input`、`.select`、`.textarea` 高度 = 點擊區，1.5px 外框，焦點時藍框加光暈。開關用 `input.switch`（原生 checkbox，`v-model` 照舊）。單選一組用 `.seg`，目前項是實心藍。
- **彈窗** `.scrim` ＋ `.modal`：手機是底部滑出的面板，iPad 以上置中。關閉鈕在右上，點擊區 ≥ 48。
- **提示訊息** `.toast`：反白底（淺色是黑底白字），手機在底部操作列上方置中，桌機在右下角。
- **危險動作**：刪除、清空用 `btn-danger`，位置放在次要處。「全部重設」只在「系統設定 → 系統維護」。

## 5. 頁面規則

| 頁面 | 區塊順序 | 備註 |
|---|---|---|
| 抽籤工作台 | 標題 → 概況（四個數字一排） → 抽籤動作（抽一人、抽全部、清除） → 分配表（狀態標籤、匯出列、分配表、免掃地成員） | 手機的抽籤動作固定在底部；概況手機 2×2 |
| 名單管理 | 標題與「全部參與抽籤」 → 左：新增與匯入（手機收進可展開區塊） → 右：同學名單 | 同學列：參與開關、座號、姓名、指派、刪除 |
| 掃地工作項目 | 標題、復原、清空 → 左：新增表單（手機收進可展開區塊） → 右：類別篩選、工作列表 | 工作列表桌機是表格式，手機是卡片 |
| 歷史記錄 | 標題、排序 → 每筆可展開的記錄（匯出、刪除、各工作人員、免掃地名單） | |
| 系統設定 | 外觀 → 抽籤偏好 → 工作類別 → 匯出設定 → 備份與還原 → 系統維護（恢復預設、全部重設） | 外觀只存在這台裝置，不進備份 |

模擬頁對應檔：`mockups/抽籤工作台.html`（其餘頁面沿用同一組元件）。

## 6. 文案語氣

台灣繁體中文，直接說會發生什麼。按鈕用動詞（「增加掃地工作項目」「儲存變更」）；錯誤與提示說明原因與下一步；不使用「請注意」「溫馨提醒」之類的墊字。

## 7. 無障礙

- 文字對比 ≥ 4.5:1（大字 ≥ 3:1）；手機與 iPad 的點擊區 ≥ 48px；最小字級 14px。
- 這些由 `tests/e2e/contrast.test.js`（逐段文字量實際對比）與 `layout.test.js`（點擊區、溢出）自動檢查。改樣式後要跑，不要只憑眼睛。
- 只有圖示的按鈕要有 `aria-label`。目前頁用 `aria-current="page"`，開關狀態用 `aria-pressed`。
- 鍵盤焦點一律是 3px 藍色外框，不要移除 `:focus-visible`。

## 8. 不要做的事

- 不引入 Tailwind 或其他 CSS 框架；樣式用本文件的 tokens 與元件類別。
- 不寫死色碼、不用漸層背景、不用 `oklch()` 或 `color-mix()`、不新增色彩 token。
- 不用顏色區分工作類別、辛苦、指定；不用淡色底的卡片。
- 不在標題、統計、區塊標題放裝飾 emoji。
- 不用 `.app button { color: inherit }` 這類會蓋掉元件顏色的重設。
- 不在匯出的 PNG、PDF、Excel、Word 內容加入介面樣式或版權句；匯出樣式限定在 `.export-sheet`，永遠是淺色。
- 不把「全部重設」放回每頁都看得到的位置。
- 不另加第二個頁尾；版權句維持在既有 `<footer>`（見 TODO.md 的版權維護規範）。

## 9. 深淺色機制

- 顏色全部由 `:root` 的 tokens 提供。深色在兩處覆寫：`@media (prefers-color-scheme: dark)`（限 `:root:not([data-theme="light"])`）與 `:root[data-theme="dark"]`。
- 外觀有三種：跟隨系統（不設 `data-theme`）、淺色、深色。選擇存在 localStorage 的 `cleaning_helper_theme`，不進備份。
- `<head>` 內有一小段同步程式，在畫面繪製前套用 `data-theme`，所以深色使用者不會先閃一下亮色。
- 升級遷移：沒有 `cleaning_helper_theme` 時，舊資料存過深色的人維持深色，其餘跟隨系統。
